# ゲームデータの更新基盤

## 実装状況

`codex/tarkov-modernization`でデータ基盤・条件判定・画面接続・プロフィール保存を実装した。グラフ・一覧・詳細・FiR・ハイドアウトは新スナップショットを使う。古い画面と各画面の独立した保存処理は削除し、共通のプロフィールストアと判定へ置き換えた。

データ元は [tarkov.dev JSON API](https://json.tarkov.dev/endpoints)。通常、PvE、PvPシーズンの3モードを独立して保存する。シーズンIDが変わってもユーザーの進捗を自動削除しない。

## ローカル実行

Node.js 24とnpmを使用する。追加のAPIキーは不要。

```sh
npm ci
npm test
npm run typecheck
npm run data:update
```

単一モードを確認する場合:

```sh
npm run data:update -- --mode=regular
```

`public/game-data/manifest.json`が採用中の版を示す。各モードのファイル名はデータ内容のSHA-256で、過去版を残して新しいmanifestを最後に置き換える。差分は追加・削除・変更されたタスクID、関連データの変更有無、直前の版への参照を含む。

`.cache/tarkov-api`に応答本文・ETag・Last-Modifiedを保存し、Gitには含めない。304応答では本文を再取得しない。価格やトレーダーのリセット時刻だけが変わっても、管理対象データの版は変えない。実APIで、全45リソース中43件が304、2件は取得されたが意味のある変更がなく、manifestが書き換わらないことを確認した。

キャッシュがない初回やキャッシュの失効時には全文取得が必要。差分配信APIではないため、ETagが変わったリソースも全文を取得する。全モードのtasks・traders・hideout・items・mapsと日英辞書を、最大3件ずつ並列取得する。

## 検証と障害時

タスク・トレーダー参照、条件種別、翻訳パス、目標ID、以前のスナップショットの整合性を検証する。タスク数の20%超の減少や未対応の条件種別は更新を中止する。会話条件と内部変数はデータを保持し、利用者の確認がない限り解放済みと断定しない。

1モードでも失敗すると、新しいmanifestは公開しない。ネットワーク失敗・429・5xxは回数を制限して再試行する。以前の正常版とキャッシュを残す。中断時に参照されない候補ファイルが残る場合はあるが、manifestの採用版は変わらない。

異常な大幅変更が実際のゲーム仕様変更なら、変更内容を調査して検証ロジック・fixtureを修正する。検証を無効化して自動採用しない。

## GitHub Actions

`.github/workflows/update-game-data.yml`がUTCの0:17、6:17、12:17、18:17（日本時間9:17、15:17、21:17、3:17）に確認する。GitHub側の混雑で実行時刻が遅れる場合がある。API本文とHTTP検証子はActions cacheに保存し、次回復元する。

意味のある変更がある場合だけ、テスト・型チェック・ビルドを通したデータをmainへ通常のpushで保存し、再利用可能なPagesワークフローを呼び出す。GITHUB_TOKENのpushから通常のpushワークフローは発火しないため、明示的な呼び出しで同じデータコミットを配信する。変更がなければコミット・配信を省略する。

有効化には、ワークフローをデフォルトブランチのmainにマージし、Actionsを有効にする。mainへのActionsの書き込みがブランチ保護で禁止されている場合は更新コミットが失敗するため、リポジトリの運用設定を確認する。現在はローカルでコミットした段階で、リモートへのpush・定期実行・公開は行っていない。

仕様の出典: [scheduleの制約](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)、[GITHUB_TOKENによる再帰実行の抑止](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)、[再利用可能ワークフロー](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows)。

## 条件判定

`src/domain/progression.ts`に画面から独立した判定を置く。PMCレベル、実際の前提タスク状態（受注中・完了・失敗）、LL、信頼度、陣営、プレステージ、確認が必要な条件、起点を明示記録した待機時間を扱う。

判定結果は「条件を満たす」「既知の未達条件がある」「確認が必要」の3状態。手動で記録したゲーム内の受注可否は別に保持し、既知の不足理由を消さない。未入力の信頼度を0とみなさず、LL計算にも未解放・不明を反映する。APIの内部変数から未検証の配布グループのOR条件を推測しない。

30件のテストで、条件の境界値、未知条件、304・HTTP失敗、翻訳と代替品の保持、内容ハッシュ、モード途中の失敗、以前の版の破損、プロフィール移行・復元・シーズン分離、グラフの循環、アイテムの集計を確認する。CIでは全体のlint・型チェック・ビルドも実行する。

## プロフィールと画面

`tarkov-helper-profiles-v1`にスキーマ付きの全プロフィールを保存する。通常・PvE・シーズンID別に分離し、未知のタスクIDや割当が不明な旧アイテム記録も残す。旧完了タスク・PMCレベル・アイテム記録・非対象の施設は初回だけ読み取る。旧キーの変更・削除はしない。

旧アイテム記録は同じアイテムが複数の納品目標に使われる場合に自動割当しない。代替候補への記録は1目標の合計数として上限まで移行する。旧施設の完了記録はIDを保持したうえで建設済みレベルへ反映する。未割当の記録はバックアップに保持し、画面で件数を表示する。

保存の失敗や破損時はエラーを表示し、既存データを黙って上書きしない。復元ではスキーマ・数値・状態・IDを検証し、プロフィールごとの完了数を表示してから利用者が適用する。同じタブには即時通知し、別タブのstorageイベントも反映する。

ブラウザはmanifestを起動時・プロフィール変更時・手動再確認時に取得する。スナップショットのSHA-256・モード・シーズン・スキーマを検証してから採用する。古いシーズンのプロフィールには最後に使った版を残し、現在のシーズンへ進捗を転用しない。

日英タスク／アイテム検索、お気に入り、未完了・受注中・要確認フィルター、APIフラグによるKappa／Lightkeeper関連表示、マップ別の受注中の未完了目標、キー候補の重複集約、マーカーの消耗数量を実装した。施設と納品目標へのアイテム割当は別々に記録する。

残る検証・拡張: 配布グループのOR条件とLightkeeper入口の補正、更新差分の名前付き履歴と既読管理、レイドの任意目標選択・複雑な装備指定、複数タブの同時書き込みの競合解決、端末内の最終正常スナップショットの永続キャッシュ。現在の再取得失敗では同じページで最後に読み込めたデータを残すが、ブラウザ終了後の完全オフライン動作は保証しない。

依存関係はNext.jsと対応するESLint設定を16.3.8へ更新し、互換性を保てるロックファイルの修正を適用した。本番依存のnpm監査は0件。開発依存には、ESLintの間接依存bracesに修正版がない問題が残る（監査では5パッケージに伝播して表示）。Next.js用のESLint設定を14系へ戻す強制修正は行わない。出典: [Next.jsのWindowsサーバーに関する修正](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36)。
# タスク状態による信頼度の記録とLL列

完了時は `finishRewards.traderStanding`、失敗時は `failureOutcome.traderStanding` の全トレーダー分を符号付きで反映する。参照形式は [tarkov.dev APIのスキーマ](https://github.com/the-hideout/tarkov-api/blob/main/schema-static.mjs) と保存済みJSONで確認した。受注時報酬はこの処理の対象外。未入力の信頼度は0から加算するので、実際の現在値はトレーダー設定から調整する。

プロフィールの `taskReputation` に実際に反映した差分を保存する。同一状態への再設定は何も加算しない。取り消し・失敗への変更では記録した旧差分だけを戻して新差分を反映し、手動調整や後のAPI報酬変更を保護する。既存の完了済みタスク・復元データには遡って加算しない。

グラフは左からLL1〜LL4、LL要確認の列に配置する。本人トレーダーのAPIの明示LL条件を優先し、明示条件がないものには補足JSONの `supplementLoyaltyLevel` を使用する。分類もなく内部条件があるタスクはLL要確認へ、両方ないものはLL1へ置く。補足LL分類は受注条件に追加しない。LL1列はすべて受注可能という意味ではなく、PMCレベル・前提タスクなどの判定は別途行う。

前提が受注中・完了を必要とする経路もたどり、本人トレーダーのLL分類の最大値を表示列へ継承する。The Punisher Part 5・6はPart 4のLL4からLL4列へ配置し、ノードと詳細に「前提経由」と根拠を表示する。検索で非表示の前提も、同じモードの全タスクから参照する。別トレーダー自身のLLは流用せず、失敗を許す経路では継承しない。循環・欠落した参照があっても探索を終了する。これは前提を受注するまでのLLに基づく表示分類であり、完了済みの前提のLLを現在の受注条件に追加しない。

## タスクラインのフォルダ表示

同じモードの全タスクから前提・後続を調べ、2件以上続く一本道をフォルダ化する。LLの違いやLL不明では分断しない。複数前提、他トレーダーのタスクを前提とするタスクはフォルダから外す。同じトレーダー内の分岐点はフォルダの末尾に含め、後続を別のラインとして扱う。フォルダ内部には分岐を含めない。Health Care Privacy Part 1〜4は同じフォルダになり、Part 4から複数の後続へ接続する。他トレーダーへの後続はフォルダの分岐判定に含めない。The Punisher Part 6はThe Choice（Fence）へ続くが、Punisherのラインに含める。失敗を許す前提、循環もまとめない。検索・状態・目標の絞り込みで関係を削ってから検出しない。他トレーダーの前提があるタスクを外した残りの一本道が2件以上あれば、その区間だけをまとめる。

フォルダは先頭タスクのLL列に置き、クリックでその下に前提順で縦に展開する。展開した見出しとタスクを共通の枠と薄い背景で囲む。各列の個別タスク・フォルダはPMC必要レベルの昇順、同レベルなら直接の前提タスク数の昇順に並べ、同値はIDで安定させる。フォルダのソートには先頭タスクを使う。左下のn/mは個別ノードでは満たした前提数／全前提数（受注中・失敗などもAPI指定の状態で判定）、フォルダでは完了数／格納数。右下には継承後のLL分類、フォルダには含まれるLLを表示し、LL不明は「LL要確認」とする。全メンバーが表示対象の場合のみフォルダを使い、一部だけが対象なら個別表示する。検索中・選択中は自動展開し、検索を解除または詳細を閉じると手動の展開状態に戻る。折りたたんだラインに接続する前提線はフォルダへ付け替え、内部の線だけを隠す。進捗・信頼度の更新と受注判定は各タスク単位のまま保持する。展開状態はページ内だけで保持し、プロフィールには保存しない。

ノードの件数は「完了 n/m」（フォルダ内の完了数／格納数）と「前提 n/m」（前提の充足数／全前提数）で区別し、説明をグラフ下とツールチップに表示する。前提がない0/0は非表示、未達の0/1や未完了の0/5は表示する。フォルダの重複する「n件」表記は削除した。PMCの必要レベルは左上に「レベル n～」と表示し、要求のない場合は表示しない。フォルダでは先頭タスクの必要レベルを表示する。個別タスクの右上は完了報酬の経験値とお金を表示し、finishRewards.itemsの通貨IDからルーブル・ドル・ユーロを別々に集計する。装備などのアイテムは金額に換算しない。金銭報酬がなければ「お金なし」とする。値はAPIの基本報酬であり、フォルダ見出しには報酬を合算表示しない。

グラフの受注可能なタスクは緑色にし、「未受注」「受注中」「条件を満たす」の文言は表示しない。既知の条件不足は「条件未達」、未確認の条件は「要確認」、記録した完了・失敗はそれぞれ保持する。表示だけを変え、プロフィールの受注記録を自動変更しない。詳細の後続タスク表示は追加しない。

## 配布グループの補足JSON

`src/data/progression-overlay.mjs` が [tarkov-data-overlay](https://github.com/tarkovtracker-org/tarkov-data-overlay) の公開JSONをデータ更新ごとに1回取得する。既存の6時間cronでも同じ処理が走る。ETagが同じなら304の検証済みキャッシュを使い、変更時は上流のSHA-256方式（`$meta.sha256` を除いて `JSON.stringify(value, null, 2)`）を検証する。固定した配信元のmainを追跡し、採用した版・digestをスナップショットのsourcesへ記録する。digestは内容の整合性であり、署名ではない。取得・検証失敗は更新を止め、既存manifestを維持する。

取り込むのはモード別の `progressionCounters` と本人トレーダーのLL分類のみ。その他の補正、陣営、ストーリー条件、報酬、前提の削除はこの実装では取り込まない。これらを勝手に混ぜると独立した条件を上書きするため。LLの分類だけで新たなLLゲートやLL到達によるOR経路を推論しない。

対象版は1.1.0。`verified` / `complete`、対応revision一致、全対象タスクが現在モードに存在する場合のみ、記録された完了タスクをID単位で数える。未受注・受注中・失敗は0、完了は1、取消時も再計算する。未記録はこのアプリの未受注として数えるため、ゲーム内進捗は利用者が入力する必要がある。手動確認を指定するとその判定を優先し、「自動判定を使用」で戻せる。APIの条件の比較演算子は保持する。

実測した補足版1.128は各モード27グループ中23が検証済み、Mechanic LL3/LL4、Prapor LL4、Ragman LL1の4グループが未解決。将来の版変更、対象タスク欠落、未解決は自動判定を行わない。対象タスクの一覧と不足数、検証資料のリンクを詳細に表示し、人数条件をすべての前提タスクのANDに変換しない。コミュニティの実測に基づくモデルでありゲームの完全再現とはしない。[根拠と制約](https://github.com/tarkovtracker-org/tarkov-data-overlay/blob/main/docs/GLOBAL_VARIABLES.md)。MITライセンスの通知は `docs/TARKOV_DATA_OVERLAY_LICENSE.txt` に保存している。


## グラフ上の完了操作と詳細

タスク画面はグラフを初期表示し、下部に詳細一覧を並べない。通常クリックは完了／未受注の切り替えで、既存の信頼度台帳を経由して報酬を加算・取り消す。条件の予測にかかわらず利用者がゲーム内の完了を記録できる。Shift＋クリックまたは右クリックは詳細のみをモーダルで開く。キーボードのEnter／Spaceも同じ切り替え、Shift併用は詳細。フォルダは展開・折りたたみのみで、一括完了しない。詳細は標準dialogでフォーカスを囲み、Esc・閉じる・背景クリックで閉じる。前提リンクのtaskハッシュも詳細を開く。一覧に切り替えた場合は名前と詳細ボタンだけを表示し、長いグラフの説明文は折りたたむ。アイテム管理の詳細表示は維持する。

グラフ画面は最大横幅を設けず、100dvhの縦レイアウトでヘッダー・検索・操作説明を除く残りの高さをグラフへ割り当てる。グラフの最低高は320pxで、狭い画面や設定を開いた場合はページの縦スクロールを許す。その他の画面の本文は従来の最大幅を維持する。上部ナビゲーションは16〜18pxの文字と広いクリック範囲を使用する。

## 全トレーダーの関連ライン

全トレーダーをまとめたグラフは、APIのtaskRequirementsで異なるトレーダー間の接点を持つ連結ラインだけを表示する。前提・後続を双方向にたどり、同じトレーダー内の前後と接続する枝も含める。失敗を要求する前提も関係として扱い、欠落した参照や共通の内部カウンターから新たな線を推測しない。全カタログから対象を求めた後に検索・状態・目標フィルターを適用する。各トレーダーの個別グラフと、明示的に切り替えた一覧は全タスクが対象。完了数の分母も表示スコープにそろえる。

統合グラフはLLで列分けせず、前提の最長経路の深さ（前提なし＝深さ1）を列に使う。同じ深さは縦に並べ、従来どおりPMCレベル・前提数で並び順を決める。深さは絞り込み前のモード全体で求める。統合グラフではラインを個別ノードに展開して表示し、LLは右下に残す。個別トレーダーのLL列・フォルダ表示は維持する。

個別トレーダーのグラフもフォルダ化を使わず、左側にトレーダー内の前提・後続があるタスクを深さ順で配置する。右側はそのトレーダー内に接続がない単独タスクをLL列へ配置する。分類と深さは絞り込み前の同トレーダー全タスクで計算し、別トレーダーの前提だけがあるノードは単独側に置く。LLはライン側でも各ノード右下に残す。

ホバーは選択タスクの前提と後続を双方向の各探索でハイライトし、無関係なノード・線を薄くする。ノード配列はホバーで作り直さない。深さ列の見出しとLL要確認の見出しは表示せず、LL1〜LL4だけを表示する。未分類のタスク自体は削除しない。ライン配置は非連結のラインを縦の別領域へ分け、前提・後続の位置を使う反復整列で分岐間の交差を減らす。複雑な合流や長い前提線の交差を完全には保証しない。

## トレーダー画像とFiRの確保操作

半透明ノードは通常クリック・Enter・Spaceで完了できない。Shiftクリック・右クリックでは詳細を開ける。詳細の受注条件メニューは「条件自動判定」「条件を無視して受注可能にする」の2種類。要確認（不明条件があり、既知の未達条件がない）タスクでは「ゲーム内の表示」として「出ていない」「出ている」の2択にする。手動解放後も元の条件から文言を選ぶため、解放・取り消しでメニューが変わらない。自動判定は現在の条件に従い、条件未達・未確認なら半透明にする。旧バックアップの強制ロックも自動判定として扱う。手動解放は受注中を記録し、完了報酬は加算しない。切り替え時は現在の完了・失敗・受注記録を解除し、過去に反映した報酬を巻き戻す。上書きはプロフィールとバックアップに保存し、セルフワイプで消去する。元の解放条件の不足理由は上書き後も詳細に残す。ホバー中はノードを5%拡大し、透明な8pxの当たり判定を追加する。配置とレイアウト用の寸法は変えない。

表示フィルターは「すべて・受注中・お気に入り」の3種類をプロフィールに保存し、トレーダー移動・再読み込みでも維持する。受注条件を満たした未完了タスクも受注中に含める。グラフは受注中を灰色、未達を灰色半透明、未確認を黄色縁半透明、完了を緑、失敗を赤で表示する。タスクの状態選択は受注中・完了・失敗のみ。完了前の状態を保存し、クリックによる完了取り消しはその状態に戻す。旧データに完了前の記録がない場合は未受注へ戻し、受注可否を再判定する。お気に入りは星と金色の枠で強調し、完了時に解除する。空のLL列の見出しは表示しない。

「設定」のセルフワイプは確認後に選択中のプロフィールのタスク・アイテム・ハイドアウト・スキル・トレーダー進捗・お気に入り・手動確認を初期化し、PMCレベルを1へ戻す。プレステージ・陣営・表示設定・使用データ版と他プロフィールは保持する。同じ画面にいる間は直前の状態へ戻す操作も提供する。画面移動後の復元には書き出したバックアップを使う。

トレーダー設定・選択ではMr. Kerman、Voevoda、Taran、Radio station、Survivorを表示しない。手動の解放状態入力は廃止し、JaegerはIntroduction（5d2495a886f77425cd51e403）、RefはEasy Money - Part 1（66058cb22cee99303f1ba067）の完了状態から解放を判定する。完了を取り消したら再び未解放。保存済みの旧unlockedフラグは判定に使わない。他トレーダーのLL計算はPMCレベル・信頼度の入力で行う。

FiR・Collectorページはアイテムカードのみを表示し、下部のタスク詳細一覧は表示しない。必要タスクのリンクからトレーダー画面の詳細を開ける。

New BeginningはwikiLinkの到達先プレステージ番号で区別する。「現在のプレステージ」は達成済みの回数（初回前は0）で、次の番号のタスクだけをグラフ・一覧・FiRに表示する。未入力ではFiR集計から除外し、入力を促す。通常のrequiredPrestigeは従来どおり下限として扱うが、New Beginningは現在値の一致を要求する。進捗はタスク・目標IDごとに保持し、入力変更で他段階の記録を消さない。

通常モードのAPIには1〜4段階が存在する。5・6段階は既存の検証済みoverlay.tasksAddから限定的に取り込み、アイテム・トレーダー参照を解決する。APIが同じwikiLinkのタスクを提供したら追加を停止する。補足には全解放条件が揃っていないため「要確認」とし、完全な受注判定を保証しない。PvE・シーズンには通常モードの補足を適用しない。次の段階が未収録の場合はその旨を表示し、別段階を代用しない。

トレーダー選択は保存済みAPIのimageLinkを表示し、全トレーダーへのボタンも並べる。アイテム画像はitems.iconLinkを使用し、取得できない画像は名前にフォールバックする。FiR一覧とハイドアウトのアイテム画像は、1個要求なら確保／取り消し、複数要求なら1個追加する。必要数を満たすと緑枠になり、減算・数値入力でも修正できる。FiRの確保済みカードを残し、必須納品の同じアイテムは共通の総数を表示する。増分だけを前の未充足目標へ、減算は後ろから割り当て、既存の他目標の記録を再配分しない。いずれかの候補は1つの目標カウンターを共有し、各候補に重複計上しない。タスクや建設の完了状態は自動変更しない。
